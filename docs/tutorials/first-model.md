# Tutorial: build your first student model

In this tutorial you run the complete BrainForge loop on a non-security
domain (IT ticket triage), from raw cases to a distilled dataset and a
trained student, without spending a cent on API calls: the mock provider
plays every teacher and the judge. By the end you will have inspected a
real `dataset.jsonl` with contamination stats, exported TRL-ready splits,
and seen exactly where a GPU run picks up.

No API keys are needed. The training step needs a CUDA GPU and the training
extra; everything before it runs anywhere. Estimated time: 10 minutes.

## Prerequisites

- Python 3.12+ and [mise](https://mise.jdx.dev) (or any uv 0.12.x)
- The BrainForge repository cloned
- For the training step: a CUDA GPU and `uv sync --extra training`

## 1. Install

```bash
cd brainforge
mise install
uv sync
```

**Checkpoint**: `uv run brainforge --help` prints the command groups
(`config`, `models`, `roles`, `teacher`, `pipeline`, `rag`, `dataset`,
`train`, `quickstart`, `abliterate`).

## 2. Validate the configuration

```bash
uv run brainforge config validate
```

**Checkpoint**: `configuration is valid`. The shipped config wires four
providers (OpenRouter, OpenCode Zen, MLGW, mock), four models, six roles and
five pipelines, including `ticket_triage` for this tutorial.

## 3. Run the pipeline (mock provider)

```bash
uv run brainforge pipeline run ticket_triage \
  --input examples/cases/ticket-password-reset-001.json \
  --provider mock
```

The mock provider generates schema-valid output from each role's JSON
Schema, so the full teacher -> critic -> judge -> quality-gate path executes
offline. Three example tickets ship in `examples/cases/` (password reset,
VPN outage, invoice question).

**Checkpoint**:

```text
ticket_triage: 3 accepted, 0 rejected (3 cases) -> datasets/ticket_triage.jsonl
```

## 4. Inspect the dataset

```bash
uv run brainforge dataset inspect datasets/ticket_triage.jsonl
```

**Checkpoint**: per-record verdicts (`triaged`, `escalated`,
`insufficient_information`), teacher/judge agreement, and contamination
tags. With the mock provider, all records carry mock verdicts: the point is
the plumbing, not the labels.

## 5. Export training splits

```bash
uv run brainforge train prepare datasets/ticket_triage.jsonl
```

**Checkpoint**: `datasets/prepared/` contains `train.jsonl`,
`validation.jsonl`, `test.jsonl`, `test_postcutoff.jsonl` and
`stats.json`.

## 6. Quickstart the whole chain (dry run)

```bash
uv run brainforge quickstart run --domain ticket_triage --provider mock
```

**Checkpoint**: the chain runs pipeline -> prepare -> train, then stops
cleanly with `no CUDA device available` (or trains if you have a GPU and
the training extra). Either way the dataset and splits from steps 3-5 are
regenerated by the command itself.

## 7. Train for real (GPU)

```bash
uv sync --extra training
export OPENROUTER_API_KEY=... ZENCODE_API_KEY=...
uv run brainforge quickstart run --domain ticket_triage --input data/raw
```

**Checkpoint**: a run directory under `experiments/` with the adapter and
`train_summary.json`, then an `evaluated` line with eval loss.

## 8. Ship it (optional)

```bash
uv run brainforge train export --model experiments/quickstart-... \
  --format gguf --ollama triage-bot
ollama run triage-bot
```

Distribute the GGUF with llmp2p (`llmp2p import --ollama models/export`,
then `llmp2p seed`). See
[ship to Ollama](../how-to/ship-to-ollama.md).

## What you learned

- A domain pack (here `ticket_triage`) defines teacher/judge schemas,
  prompts and quality gates; the engine runs any domain the same way.
- The mock provider makes the entire verification path free and offline.
- `quickstart` chains everything; `--strategy full` is the heavier phase
  after a quick QLoRA pass proves the dataset.
- Security is not special: it is the reference pack where the
  contamination and judge-independence machinery was proven, and every
  other domain inherits it.
